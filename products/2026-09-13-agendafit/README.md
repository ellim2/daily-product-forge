# AgendaFit

## 문제
회의 아젠다는 시간 상한이 없으면 항목별 예상 시간이 회의 길이를 넘는지 알아차리기 어렵고, 실제 회의에서 중요한 결정을 위한 시간이 사라진다.

## 대상 사용자
30~60분짜리 반복 회의를 준비하는 팀 리드, PM, 진행자.

## 가치 제안
**AgendaFit**은 회의 총시간과 고정 버퍼를 기준으로 아젠다의 사용 시간·초과 시간을 즉시 계산하고, 초과 시 각 항목을 비례 축소한 현실적인 시간 예산을 제안한다. 계정·서버·업로드 없이 브라우저에서 작동한다.

## 이번 범위
- 회의 제목, 총 길이, 마무리/전환 버퍼, 아젠다 항목/예상 시간 입력
- 사용 가능 시간, 합계, 여유/초과, 항목별 상태 및 비례 축소 제안
- 예시 불러오기, 브라우저 로컬 저장, 인쇄용 요약
- 정적 HTML/CSS/JS 및 Node 기반 로직 테스트

## 제외 범위
캘린더 연동, 공동편집, 사용자 계정, 서버 저장은 포함하지 않는다.

## 명시적 가정
- 사용자는 항목별 예상 시간을 대략적으로 알고 있다.
- 버퍼는 아젠다에 배정할 수 없는 시간이다.
- 초과 시 모든 항목을 동일 비율로 줄이는 것은 **제안**일 뿐, 중요도/의존성은 진행자가 판단한다.

## 조사 신호와 근거
- Atlassian은 효과적인 회의를 위해 목적과 아젠다를 미리 정하고, 각 항목에 시간을 배정하도록 권한다. 이는 시간 예산을 눈에 보이게 하는 도구의 문제 적합성 신호다. [How to run effective meetings](https://www.atlassian.com/blog/productivity/how-to-run-effective-meetings) (2026-09-13 접근 확인)
- Todoist는 Pomodoro 방법을 작업에 시간 블록을 부여하는 방식으로 설명한다. 시간 제한을 명시하는 행동 패턴이 널리 쓰인다는 보조 신호다. [Pomodoro Technique](https://www.todoist.com/productivity-methods/pomodoro-technique) (2026-09-13 접근 확인)

## 핵심 불확실성
진행자가 실제로 ‘비례 축소’보다 중요도 기반 재배치를 선호할 수 있다. 다음 검증에서는 최소 3명의 회의 진행자에게 인쇄 요약과 중요도 순서 정렬 중 무엇이 더 유용한지 확인한다.

## 실행
브라우저에서 `index.html`을 열거나 아래처럼 로컬 서버를 실행한다.

```bash
python3 -m http.server 8000
# http://localhost:8000 접속
```

브라우저 기반 테스트는 Chrome Headless로 `test-browser.html`을 열어 실행한다. (별도 패키지 없음)
